# Telegram 精确基建配置

本功能只同步精确基建人员方案。它不启动/停止挂机，不处理账号密码、token、槽位、日志或其他配置。

所有者使用 `--owner-id` 配置自己的 Telegram 用户 ID；编辑者由所有者发 `/invite` 生成绑定码后 `/bind` 绑定（也可用 `--editor-id`/`--editor-account` 预先指定）。机器人会识别一图流/MAA 自定义基建 JSON。所有者必须先 `/select` 选账号（见下文「选账号是前提」）；编辑者上传后直接写入绑定账号，所有者上传生成草稿并返回预览，只有所有者发送 `/publish 草稿ID` 才会写入本地配置。

启动示例：

```powershell
python -m remote_control.telegram_bot `
  --token "$env:MAA_TELEGRAM_TOKEN" `
  --owner-id 123456789 `
  --editor-account-label A `
  --invites D:\1\.telegram\invites.json `
  --project D:\1 `
  --drafts D:\1\.telegram\drafts.json
```

你发送 `/invite` 生成绑定码，另一位发送 `/bind 绑定码` 即可自动绑定到 A；绑定码 10 分钟有效且只能使用一次。

机器人启动时会自动设置命令菜单。编辑者可从菜单选择 `/start`、`/upload`、`/config`、`/bind`；所有者额外拥有 `/invite` 和 `/publish`。选择 `/upload` 后直接发送基建 JSON 文件；选择 `/config` 可查看当前精确基建配置。

`/config` 输出为手机可读的排版（按批次列出控制中枢/会客室/制造站/贸易站/发电站/宿舍/办公室/加工站与干员，留空位显示「自动」）。所有者发送 `/config` 先看账号列表，再用 `/config 编号` 或 `/config 名称`（如 `/config 2`、`/config 官服2`）查看单个账号；编辑者发送 `/config` 直接查看绑定的 A 账号。输出不包含密码、token、路径等敏感字段。

上传成功后的回执包含：变更对比（哪些批次哪些房间的干员/产品变了）、导入注意项（文件里控制台不支持的字段，如 groups/skip，仅导入 operators）、以及所有者的草稿 ID。编辑者上传直接写入绑定账号；所有者上传生成草稿，回复 `/publish 草稿ID` 发布。

## 选账号是前提

所有者先 `/select` 选择要操作的账号，之后一切命令（`/config`、`/upload`、`/presets`、`/preset …`、`/invite`、`/publish`）都只作用于该账号：

- `/select` 直接回复账号按钮（一行一个账号），点按即选中，无需输入编号；`/select 编号` 仍可作为文本方式兜底。
- 未选账号时，机器人聊天菜单只显示「开始 / 选账号 / 帮助」，其余命令按钮隐藏；选中后菜单才展开全部命令，`/select` 可随时换账号。
- 选中状态持久化在 `--selection` 文件（默认与 drafts.json 同目录的 `selection.json`），机器人重启不丢；选中账号被删除时自动回到未选状态。
- 编辑者不需要选账号：固定绑定账号（`/bind` 后菜单自动展开）。
- 所有者上传不再需要文件说明（caption）——目标就是当前选中的账号；上传生成草稿后，只有在选中同一账号时才能 `/publish` 发布（换过账号会提示先切回去）。
- `/invite` 生成的绑定码绑定**当前选中账号**（不再固定于启动参数指定的账号）；编辑者绑定各自的账号，互不影响。

## 预设

控制台里每个账号各自的基建排班预设（`base_schedule_presets`，账号之间不互通）也可以在 Telegram 里查看、管理和使用，全部针对当前选中的账号：

- `/presets` — 当前账号的预设管理页：每条预设一行按钮 [📄 查看] [▶ 应用] [🗑 删除]，点击直接执行。查看/应用在消息上原地展示，删除需再点一次「确认删除」；按钮按「账号 + 预设名摘要」校验，切换账号或预设变动后旧按钮自动失效。
- `/preset show <名称>` — 查看预设内容（文本方式，排版与 `/config` 详情一致）。
- `/preset use <名称>` — 应用预设：布局/无人机取预设，批次按名字匹配覆盖，预设里没有的批次保留当前内容；不改变启用状态。回执带覆盖/保留批次与变更对比。
- `/preset save <名称> [覆盖]` — 把当前排班存为预设（需输入名称，保留文本命令）；同名已存在时须加 `覆盖` 参数（原地覆盖，与控制台一致）。
- `/preset del <名称>` — 删除预设（不影响已应用到的排班）。

## 命令引导

- 菜单命令用两三个字的短标注（查看配置 / 预设管理 / 发布草稿…）。
- `/help` 是一行一条的命令速查（命令 + 简短标注），按角色显示。
- 每一步回复末尾直接给下一步命令：`/select` 与 `/presets` 都是按钮操作（点按即执行），`/preset show` 的文本回复带应用/删除命令。
- 预设名允许空格（与控制台一致），文本命令里用「」包住即可，如 `/preset use 「333 日常」`；不加引号时只取第一个词当名称。
- `/start` 显示当前角色与绑定账号，并提示 `/help`；未知命令提示发送 `/help`。

健壮性约定：长轮询出错只记日志并退避重试，单条消息处理失败不影响机器人运行；轮询进度持久化在 `--state` 文件（默认与 drafts.json 同目录的 `poll_state.json`），重启后从上次位置继续，不会重放旧消息；`/bind` 过的编辑者绑定保存在 invites.json，重启后自动恢复（CLI `--editor-id` 指定的优先）。机器人只处理私聊消息；每条消息处理前都从磁盘重读 `config.json`，写入时基于最新配置套用补丁，不会覆盖 GUI 在机器人运行期间的修改。

草稿文件只放在本地，不上传到 VPS。建议把机器人作为 Windows 计划任务/后台进程运行，使用环境变量保存 Bot Token；配置改动沿用 `config.json` 的原子写入和每日备份。
