# 编辑者直接写入基建设计

## 意图

绑定到账号 A 的 Telegram 编辑者上传基建 JSON 后，立即把结果写入本地配置中的 A 账号；所有者仍可管理全部账号并使用草稿发布流程。

## 范围

- 编辑者只能操作绑定账号，上传时忽略文件说明中的账号 ID。
- 编辑者只看到自己的处理结果，不提供账号列表或其他账号配置。
- 写入前沿用项目现有配置保存与每日备份机制。
- 所有者行为保持不变：上传生成草稿，发送 `/publish <草稿ID>` 后写入。

## 方案

保留所有者的草稿流程，同时为编辑者增加受权限约束的直接发布分支。这样不改变所有者现有操作，也不需要把草稿状态或其他账号数据暴露给编辑者。编辑者的目标账号从绑定关系取得，不能由消息内容覆盖。

## 约束与验收

- 任何编辑者上传都只改变绑定账号的 `base_schedule`。
- 其他账号的配置保持字节级等价。
- 编辑者发送任意 caption 仍只能写绑定账号。
- 写入失败时不标记草稿、不泄露其他账号信息。
