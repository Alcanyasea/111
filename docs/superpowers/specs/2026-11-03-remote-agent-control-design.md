# 远程控制平面与本地 Agent 设计

## 意图

让用户在离开电脑时通过手机管理本地 MAA 挂机系统：查看账号与运行状态，触发整轮挂机或基建收菜，启停账号，维护运行班次，并编辑账号的精确基建配置。1GB 服务器只承担手机网页、认证、命令队列和状态存储；模拟器、MAA、账号密码、槽位数据和本地日志仍留在 Windows 电脑。

## 成功标准

- 手机浏览器可以安全登录并查看本地设备、账号、当前运行、最近运行结果和计划。
- 手机发出的“立即运行”“基建收菜”“停止”“启用/停用账号”“修改班次/基建配置”能在本地电脑在线时执行，并显示成功或失败原因。
- 本地电脑离线时，服务器保留待执行的配置变更和一次性命令；重新上线后按顺序处理，重复提交不会重复启动挂机。
- 服务器常驻内存适合 1GB 主机，并能与现有服务通过独立端口、独立目录和独立进程身份共存。
- 现有桌面 GUI、计划任务和脚本流程继续可用；远程操作不会绕过 `master.lock`、单实例控制台锁或现有配置备份机制。

## 范围

第一版包含：

- 一个响应式 Web 控制台，适配手机，不要求安装原生 App。
- 一个 Windows 本地 Agent。Agent 只主动向服务器发起 HTTPS 长轮询或 WebSocket 连接，不要求家庭网络入站端口。
- 设备配对、登录会话、撤销设备和单设备审计记录。
- 远程读取账号标签、服务器、启用状态、运行顺序、槽位是否存在、计划和精确基建配置摘要。
- 远程执行完整挂机、基建收菜、停止当前运行、切换账号，以及账号启停和顺序调整。
- 远程编辑班次时间、启停和账号筛选，以及精确基建的批次、设施干员、无人机和菲亚梅塔配置。
- 配置版本、冲突检测、原子写入和本地回滚备份。

远程账号编辑只包含显示名、启用状态、运行顺序、第二理智候选关卡和精确基建字段；账号密码、登录捕获、token、uid 和槽位文件始终由本地桌面 GUI 管理。

不包含：

- 在 1GB 服务器上运行 Windows、MuMu、MAA 或屏幕识别。
- 把账号密码、登录 token、`scripts/accounts`、MAA `gui.json`、完整日志或失败截图上传到服务器。
- 让服务器执行任意 PowerShell、shell 或文件路径命令。
- 把现有挂机脚本改造成服务器端执行器。
- 多用户协作、公开注册、原生手机 App 和云端账号托管。

## 约束与安全边界

当前仓库的控制台是 Windows/PySide6，运行主体依赖 MuMu、ADB、MAA 和 PowerShell 7。因此服务器只能做控制平面，本地 Agent 才能执行实际动作。服务器默认按 Linux + systemd 或独立 Docker Compose 项目部署；如果现有服务使用其中一种方式，远程控制平面使用自己的目录、服务名、端口和资源上限，不修改现有服务的容器、卷或启动参数。

服务器使用 SQLite 保存设备、命令、配置快照和审计记录，数据库与现有服务目录分离。Web 服务只监听配置的地址；公网部署必须经过 HTTPS，管理接口默认需要强密码和配对令牌。设备令牌只在注册时显示一次，服务器端保存哈希；撤销后本地 Agent 必须停止接受远程命令。命令按类型白名单校验，参数使用结构化 JSON，不允许传入脚本路径或原始命令行。

账号密码和槽位数据只在本机 `config.json`、环境变量和 `scripts/accounts` 中存在。服务器端只保存账号 id、显示名、服别、启用状态和槽位存在性等最小状态。远程编辑账号时，服务端发送配置补丁，本地 Agent 在写入前创建带时间戳的备份；补丁基于配置版本号，版本不一致就拒绝覆盖并回传冲突，让手机先拉取最新状态。

## 方案与取舍

### 方案 A：服务器控制平面 + 本地 Agent（选用）

服务器提供认证、命令队列、配置版本和手机 Web 页面；Agent 通过出站连接领取命令，在本机复用已有 Python 配置模块与 `runner`，再把结果回传。它符合“传数据到本地执行”的需求，服务器资源小，不需要开放家庭网络端口，也能与当前服务隔离。代价是要增加一套协议、Agent 生命周期和冲突处理。

### 方案 B：服务器只做 VPN/反向代理

手机通过 VPN 或反向代理访问本地桌面控制台。实现量较小，但需要远程桌面或浏览器转发，移动端操作不适合复杂的账号/基建配置；本地 GUI 也没有稳定的远程 API，后续仍要补接口。

### 方案 C：服务器只同步文件

手机修改加密配置文件，电脑定时下载并执行。资源和实现成本最低，但无法可靠表达“停止当前运行”、状态回传和命令去重，配置冲突与损坏恢复也更难控制。

选择方案 A，因为它能提供即时控制和状态反馈，同时把高资源、强耦合的模拟器工作留在原来的本地环境。

## 组件设计

### 服务器

- `control-server`：轻量 HTTP API 和响应式页面；使用单进程、可配置并发上限。
- SQLite：`devices`、`commands`、`config_documents`、`status_snapshots`、`audit_events`。
- 命令状态：`queued`、`claimed`、`running`、`succeeded`、`failed`、`expired`、`cancelled`。
- 每个命令有 `command_id`、目标设备、幂等键、创建时间、过期时间和结构化参数。启动类命令默认同一设备只允许一个未完成实例。
- 状态和配置接口只返回脱敏摘要；完整日志按行摘要上传，密码、token、槽位内容和截图不上传。

### 本地 Agent

- 以 Windows 后台进程运行，和 GUI、计划任务分开；Agent 崩溃或断线不终止现有挂机。
- 连接服务器后注册设备能力和本地仓库版本，持续领取命令；断线时只执行本机计划任务，不在本地缓存新的远程启动命令。
- 所有执行操作经过本地互斥层：运行/收菜/切号遵循 `master.lock`，配置写入遵循单一配置写入锁；检测到 `master.ps1` 正在运行时，返回“忙”而不强杀。
- 远程“停止”调用现有 `runner.stop()`；只有用户明确操作才允许停止，不因网络断开自动停止。
- Agent 使用现有 `appconfig.load/save`、`runner`、`scheduler` 和基建配置规范化逻辑，避免维护第二套配置格式。

### 手机页面

首屏显示设备在线状态、当前运行阶段、下次计划和最近结果；账号页显示启停、顺序和槽位状态；操作按钮在服务器生成命令后显示排队/执行/结果；基建配置使用分批次表单，保存前展示配置版本和差异。账号密码录入与重新捕获登录仍留在本地桌面 GUI，不放到手机页面。

## 数据同步与冲突

服务器保存“期望配置”的版本号，本地 Agent 上线后发送本地版本与摘要。远程修改生成补丁并排队，不直接改服务器上的完整密码配置。Agent 领取补丁后验证 `base_revision`，通过后在本地写入临时文件、替换配置并保留备份，再回传新版本；失败则保留本地文件并标记命令失败。桌面 GUI 保存时也增加同一版本检查，避免 GUI 和 Agent 互相覆盖整份旧快照。

运行状态以本地为准，服务器只保存最近快照和有限历史；服务器重启不会导致本地重复运行。命令领取使用租约，Agent 失联后租约过期，命令可重新领取；执行启动类命令前再次检查本地运行锁，保证幂等。

离线期间的启动类命令必须有短时过期时间，避免电脑数小时后上线却意外开跑；停止命令和配置补丁可采用更长的有效期。具体时长在实现前由部署选择确定。

## 并存与部署

服务器端使用独立服务用户、独立工作目录和独立监听端口；若由现有反向代理统一入口，只新增一个路径/上游，不修改原服务业务。SQLite 数据库定期做本地备份，日志限制大小并轮转。Agent 安装在项目目录之外的专用目录，配置只记录服务器地址、设备标识和令牌，不改现有 `config.json` 以外的用户文件；升级 Agent 失败时保留旧版本可回退。

## 验证

- 服务器 API、命令幂等、认证、版本冲突和租约测试使用临时 SQLite。
- Agent 测试使用临时项目目录、假 `master.ps1`、假配置和补丁写入函数，禁止读取或写入真实 `config.json`、账号槽位、日志、模拟器或 MAA 目录。
- 运行受影响 Python 文件的语法/导入检查，并按仓库要求运行全量测试：`python -m unittest discover -s tests`；GUI 测试使用 `gui/.venv/Scripts/python.exe`。
- 在测试服务器上验证 1GB 限制下的常驻内存、现有服务端口不冲突、服务重启和断线重连。
- 真实电脑联调只验证“领取命令、获取状态、配置备份和运行锁”，不把账号密码或槽位内容上传到服务器。

## 待实现者决定的细节

- 服务器实际系统和现有服务的部署方式决定使用 systemd 单元还是独立 Compose 项目。
- 长轮询还是 WebSocket：默认先用 HTTPS 长轮询，减少反向代理和连接保持要求；若状态刷新需要更快，再切换为 WebSocket。
- 手机端是否需要公网访问；若需要，必须提供域名/HTTPS 或现有安全隧道，不能直接裸露管理端口。
- 第一版是否包含远程修改班次；本设计按包含处理，因为它与账号启停和基建配置同属用户明确的离线管理需求。
- 首次配对时以本地配置为基准生成服务器初始快照；只有用户明确选择“覆盖本地”时才允许服务器快照写回本地。
