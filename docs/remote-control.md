# 手机远程控制

远程控制由两部分组成：1GB 服务器上的控制平面，以及家里 Windows 电脑上的本地 Agent。服务器只保存命令、设备状态和脱敏配置摘要；MuMu、MAA、账号密码、登录 token、槽位目录和完整日志始终留在电脑上。

服务器使用 `remote_control.server_cli` 启动，建议放在独立目录和独立服务用户下，监听与现有服务不同的本地端口，再由已有 HTTPS 反向代理转发。示例服务文件把端口设为 `18765`、数据库放在 `/var/lib/maa-control`，并限制内存为 256MB；按实际系统改成 systemd 或 Compose，但不要复用现有服务的数据卷。登录后向 `POST /api/v1/pair` 提交设备 ID 和名称，得到只显示一次的 Agent token；把该 token 配给 Windows Agent。

首次配对以本地电脑的配置为准。Agent 上线后只上传账号 id、显示名、服别、启用状态、计划和槽位是否存在；手机不能录入密码或触发登录捕获。远程修改仅覆盖启停、顺序、候选关卡、班次和精确基建字段，保存前会按 `remote_revision` 检查版本并生成 `config.json.remote-bak-*` 备份。

运行/收菜命令默认应使用短过期时间；电脑离线太久后上线，过期命令不会自动启动。停止命令由用户明确触发，网络断开不会自动停止本地挂机。Agent 发现 `master.lock` 或现有运行时会返回忙，不强杀进程。

撤销设备后，服务器拒绝该设备继续领取命令；若令牌泄露，应立即撤销并重新配对。恢复配置时先停止远程修改，再从最近的 `config.json.remote-bak-*` 或项目每日备份恢复，最后重新配对并让本地状态覆盖服务器快照。

上线检查：服务器端口不与现有服务冲突、反向代理启用 HTTPS、数据库目录可备份、Agent 能出站访问服务器、桌面 GUI 和计划任务仍能独立运行。测试时使用临时目录和假 Runner，不要把真实配置、账号槽位、日志或 MAA 文件复制到服务器。
