# 明日方舟 MAA 自动挂机系统

一键自动完成多个账号（官服/B服任意组合）的每日任务，含自动切换账号。

## 首次使用：配置账号密码（重要）

仓库中**不包含任何真实账号密码**：`config.json`（本地配置，含账号密码）和 `scripts\accounts\`（登录 token/uid 等账号数据）都被 `.gitignore` 排除，不会上传到仓库。下载代码后需要自己配置：

1. 将 `config.example.json` 复制为 `config.json`（两文件同目录 `D:\1\`）
2. 用文本编辑器打开 `config.json`，在 `accounts` 中填写自己的游戏账号（手机号/邮箱）和密码；`paths` 里的 MAA / MuMu / ADB 路径也请改成你本机实际安装位置
3. 启动 GUI 控制台（`启动控制台.bat`），或在「账号管理」页面维护账号

> 提示：不手动创建 `config.json` 也可以——GUI 首次保存设置时会自动生成空白的 `config.json`，在「账号管理」页面输入账号密码即可。登录后程序会把 token/uid 写入 `scripts\accounts\`（仅本机使用，不会上传）。

## 功能

- 每天按设定的时间点自动启动（默认 4:00 / 16:00，可在控制台增删改，Windows 计划任务）
- 自动开启 MuMu 模拟器
- **槽位切号（非点击）**：每个账号的登录数据（token/uid）保存在 `scripts\accounts\<slot>\`，切换 = 停游戏 → 推入数据文件 → 重启游戏，全程不点击
- **MAA 前登录校验**：每个号跑 MAA 前屏幕级确认已登录；token 失效时官服自动输账号密码重新登录并刷新槽位，失败则跳过该号
- 官服 ↔ B服 自动切换客户端
- 每个号完成后自动启动 MAA 执行每日任务
- 任务队列：公开招募 → 基建换班 → 剿灭(周六) → 刷1-7 → 信用商店 → 领奖励
- **精确基建派驻（可选插件）**：按账号为 6 类设施指定进驻干员（批次随启动时间
  自动划分，如 8点/12点/24点三批；333/243 布局），MAA 运行前自动套用；不启用则
  继续用 MAA 自带基建换班
- 完成后自动关闭模拟器；成功时不弹窗，仅失败时弹出提示窗口（每号耗时 + 失败详情）
- **每个启动时间可单独设置是否关机**（仪表盘「班次计划」每行一个开关）：成功后
  60 秒自动关机（无需确认）；失败则弹窗提示并保持开机
- **GUI 控制台**（`gui\`，PySide6）：仪表盘实时状态、**账号管理（增删账号/启停/捕获登录）**、图形化改配置、日志彩色查看、一键运行/停止

## GUI 控制台

**打开方式（任选）**：
- 桌面快捷方式「MAA 挂机控制台」（已创建，带图标）
- 双击 `D:\1\启动控制台.bat`
- 命令行：`D:\1\gui\.venv\Scripts\python.exe D:\1\gui\main.py`

| 页面 | 功能 |
|------|------|
| 仪表盘 | 账号状态卡片（数量随列表变化）、班次计划（**增删改启动时间**、每项启用/关机开关立即生效）、最近一次运行汇总、连接状态（含 MAA RunDirectly 检查） |
| 账号管理 | **增删账号、每号启用开关、捕获登录数据、精确基建派驻开关与配置**（输入账号密码自动登录并保存槽位；特殊字符密码/验证码自动转人工登录） |
| 运行设置 | MAA/ADB/MuMu CLI 路径、超时、关模拟器开关、**MAA 服务器一键配置（官服/B服独立按钮）**、数据清理（含 Python 缓存与生成的基建计划文件） |
| 日志 | 深色日志视图（成功绿/失败红），自动 tail、清空、打开文件 |

- 所有设置写入 `D:\1\config.json`，`master.ps1` 等脚本启动时读取（字段缺失时回退脚本内硬编码）
- 「运行设置 → MAA 服务器配置」：官服 / B服 各一个按钮，一键修正该服 MAA 的
  客户端类型、ADB 路径与地址、RunDirectly、结束脚本、常用任务启用；若该服 MAA
  目录不存在，会自动从另一服复制一份再修正（修改前先备份原配置）
- GUI 点「立即运行」时自动加 `-NoShutdown`：手动运行即使成功也**不关机**（符合人工操作预期）；计划任务照常关机逻辑不变
- 「停止」会结束 master.ps1 与 MAA 进程，并执行 `shutdown /a` 取消已排定的自动关机
- 计划任务为 **1 个任务（MAA_明日方舟自动挂机），内含 config.schedule.times 的
  全部启用时间触发**（默认 04:00 / 16:00）；仪表盘「班次计划」增删改后自动同步，
  更新需要管理员权限（否则会弹提示）
- `--smoke` 参数：加载全部页面后自动退出，用于无交互自检

## 执行流程

```
启动模拟器 → 对每个启用账号循环：
 槽位切号（停游戏 → 推入该账号登录数据 → 重启游戏，非点击）
  → 登录校验（屏幕级确认已登录；token 失效/停在登录界面时官服自动输入账号密码
    重新登录并刷新槽位数据，失败则跳过该号防 MAA 空跑）
  → 跑该服务器的 MAA
→ 关模拟器 → 弹窗通知
```

config.json 的 `accounts` 必须为**数组**（GUI「账号管理」页维护）；非数组或缺失时
master.ps1 拒绝运行（防止用旧格式跑错账号；旧点击切号流程已废弃）。

### 账号槽位机制

每个账号的登录数据（含 SDK token、uid）在首次登录后保存到 `scripts\accounts\<slot>\`：

```
accounts\<slot>\
├── uid.txt                          # 登录 UID（切换后校验用）
└── shared_prefs\                    # 镜像设备 /data/data/<pkg>/ 相对路径
│   ├── <pkg>.v2.playerprefs.xml     # 含 u8sdk_cached_uid 等登录态
│   └── HypergryphSdkPreferences.xml # 含 USER_CACHE token
└── files\zx\lc.cache
```

- **切号**（`slot_switch.ps1`）：强制停止两个客户端 → `adb push` 数据文件并修正
  owner/权限/SELinux 上下文 → 重启目标客户端 → 校验 uid 与槽位一致（不一致则该号判失败，
  防止跑到错误账号）。需要 adb root（MuMu 12 自带）。
- **登录校验**（`login_check.ps1`，master.ps1 在切号后、MAA 前自动调用）：OCR 屏幕级确认
  游戏实际已登录（文件级 uid 校验通过不代表真在登录态——token 失效时游戏会回到登录界面）。
  检测到登录界面时：官服自动用 config.accounts 里的账号密码登录（点掉首次启动弹窗/标题
  画面 → 账号登录 → 密码登录 → 输入 → 登录），成功后校验 uid 与槽位一致并刷新槽位数据
  （token 续期）；B服/无凭据/验证码则判失败，跳过该号防止 MAA 对着登录界面空跑。
- **捕获**（`capture_account.ps1`，由控制台「添加账号」触发）：清空登录态 → 重启游戏 →
  OCR 自动点掉首次启动弹窗（配音包下载/选择）→ 登录界面 → 自动输入账号密码 →
  轮询登录成功 → 拉取文件保存到槽位。密码含特殊字符或出现验证码时自动转「人工登录」：
  提示你在模拟器窗口手动登录，脚本检测成功后自动拉取。失败自动恢复原登录态。
  拉取时会在槽位 playerprefs 补写基建引导标记（`key_GB_viewed#BUILDING_STATION_MANAGE`），
  新账号首次进基建不再弹「第一次登录」引导，且后续每次都不会再出现。
- B 服单账号无需捕获也可以正常运行（槽位缺失时仅切客户端）；官服槽位缺失会拒绝运行
  该号（防止用错账号数据跑错号）。

### 关键机制

| 机制 | 文件 | 说明 |
|------|------|------|
| 互斥锁 | `master.lock` | 存当前运行的 PID，防止重复启动 |
| 完成信号 | `maa_done.signal` | MAA 跑完后由 `signal_done.ps1` 创建，`master.ps1` 轮询检测 |
| MAA 回调 | `signal_done.ps1` / `signal_done.bat` | 在 MAA 设置中配置为「任务结束后执行脚本」，指向 `signal_done.bat` |

## 安装步骤

### 1. 安装 MuMu 模拟器

- 下载安装 MuMu 模拟器 12
- 设置分辨率：**1280×720（横屏）**
- 安装明日方舟（官服）和明日方舟（B服）
- 官服内登录两个账号

### 2. 安装 MAA

- 下载 MAA（MaaAssistantArknights）v6.11.1
- 解压到 `D:\软件\MAA\MAA-v6.11.1-win-x64`
- 运行 MAA，配置连接 MuMu 模拟器（ADB: `127.0.0.1:16384`）
- 配置任务队列：公开招募、基建换班、剿灭、刷1-7、信用商店、领奖励
- 在 MAA 设置 → 「任务结束后」→ 执行脚本，填入 `D:\1\scripts\signal_done.bat`
- 复制一份到 `D:\软件\MAA（b）\`，将客户端类型改为 Bilibili，同样配置结束脚本

### 3. 部署脚本

- 将本项目 `scripts\` 目录下所有文件放到 `D:\1\scripts\`
- 将 `启动挂机.bat` 放到 `D:\1\`（根目录）

### 4. 设置定时任务

推荐直接在控制台「仪表盘 → 班次计划」增删改启动时间（保存时自动同步计划任务，
需要管理员权限）。也可以手动用 schtasks 创建（以管理员运行，示例为每天
4:00 / 16:00 两个时间点）：
```cmd
schtasks /Create /TN "MAA_明日方舟自动挂机" /TR "D:\1\启动挂机.bat" /SC DAILY /ST 04:00
schtasks /Create /TN "MAA_明日方舟自动挂机_2" /TR "D:\1\启动挂机.bat" /SC DAILY /ST 16:00
```

修改时间：
```cmd
schtasks /Change /TN "MAA_明日方舟自动挂机" /ST 08:00
```

> 注意：手动创建的任务与 GUI 保存的配置互不感知；建议只用一种方式维护。
> 每次运行属于哪一班（基建批次/关机选项）由 `config.json` 中最近一个已过的启用
> 时间点决定，例如 8点/12点/24点 三班：08:00–11:59 属 8点班，12:00–23:59 属
> 12点班，00:00–07:59 属 24点班。

## 使用方式

### 管理账号（推荐用控制台）

打开「MAA 挂机控制台」→「账号管理」页：

- **添加账号**：点「＋ 添加账号」，输入名称/服务器/账号/密码 →「开始捕获」。
  脚本会自动启动模拟器（如未运行）、清空登录态、重启游戏、点掉首次弹窗、
  输入账号密码登录，登录成功后继续点掉公告/配音选择等剩余首次弹窗、等主界面
  与「已处理」标记写入后再拉取登录数据，保证下次启动不再重复弹窗。
  密码含特殊符号（% ^ _ + = [ ] 等）或出现验证码时自动转人工登录：脚本会提示你在
  模拟器窗口手动登录，检测到登录成功后自动继续。
- **启停**：账号行右侧开关（立即生效，master.ps1 会跳过关闭的号）。
- **删除**：从列表移除（槽位文件保留在磁盘，可手动清理）。
- **重新捕获**：账号行「捕获」按钮（登录 token 失效时重新拉取）。

### 精确基建派驻（可选）

在「账号管理」页，每个账号右侧有两个新控件：

- **基建开关**：打开后，该账号运行 MAA 时使用配置好的自定义计划；关闭则继续
  使用 MAA 自带基建换班（Rotation）。
- **基建按钮**：打开配置窗口。

配置窗口里可以：

- 选布局（名称按贸易站/制造站/发电站顺序读）：**333**（贸易3台·制造3台·发电3台）或 **243**（贸易2台·制造4台·发电3台）
- 选产品类别：制造站每台可选 **赤金 / 原石碎片 / 作战记录**，贸易站每台可选
  **赤金订单 / 原石碎片订单**；计划应用时 MAA 会按类别匹配游戏内对应设施并
  设置对应配方（生成到计划 JSON 的 `product` 字段）
- 切换批次：批次随启动时间自动划分（如 8点/12点/24点）。本次运行发生在哪个
  时间点之后就用哪个批次（如 08:00–11:59 用 8点批，12:00–23:59 用 12点批，
  00:00–07:59 用 24点批），不会因为 MAA 实际执行基建时跨过整点而选错批次
- 逐个设施填写进驻干员：控制中枢 5 人、会客室 2 人、制造站 3 人/台、
  贸易站 3 人/台、发电站 1 人/台、办公室 1 人、加工站 1 人（可留空）

注意事项：

- 干员名必须与游戏内名称一致（MAA 靠截图识别干员，例如「银灰」「澄闪」）
- 某一项**全部留空**时，MAA 会自动按默认算法把该设施补满；**只填了一部分**
  时，MAA 只派你填的人，剩余位置保持空着（不会自动补位）
- **干员休整（宿舍）**：弹窗里可指定 4 间宿舍、每间最多 5 名进驻干员；全部
  留空时 MAA 按默认算法自动安排休整；填了干员的宿舍，剩余空位也会自动补满。
  生成计划时会把指定了干员的宿舍排到前面、空宿舍排后面，且宿舍一律不带排序
  （sort=false，规避 MAA 宿舍「清空→按序重选」失败导致留空位的已知问题）。
  计划始终包含 4 间宿舍——自定义模式下计划文件缺少宿舍会导致「清空宿舍但不补人」
- **加工站**：自定义模式下 MAA 不会自动给加工站派人，想派驻就填 1 个干员，
  留空则跳过加工站
- 保存后即生成计划文件（`D:\1\plugins\base_schedule\plans\<槽位>.json`），
  `master.ps1` 在每次跑该账号前自动应用，无需手动改 MAA
- 插件只依赖 MAA 官方稳定的自定义基建协议，MAA 升级不影响

### 手动运行

双击 `D:\1\启动挂机.bat`，或控制台右上角「▶ 立即运行」（不会触发自动关机）。

### 自动运行

计划任务到时间自动执行。前提：
- **电脑开机且不休眠**
- **用户已登录 Windows**

### 查看进度

打开 `D:\1\scripts\master_log.txt` 查看实时日志。

## 常见问题

**Q: 双击 bat 没反应？**
A: 检查 PowerShell 执行策略：
```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy Bypass
```

**Q: MAA 连接不上模拟器？**
A: 确认 MuMu 模拟器已开启、ADB 端口为 16384

**Q: 想改任务内容？**
A: 分别打开官服 MAA 和 B服 MAA，修改任务队列后保存

**Q: MAA 超时了（超过 30 分钟）？**
A: 编辑 `master.ps1` 中 `$maaTimeout` 值（单位：秒）。常见卡死原因：MAA 任务配置问题、模拟器卡顿

**Q: 运行完成后怎么知道结果？**
A: 成功不弹窗、无需确认；只有失败时弹出提示窗口，显示每号耗时和状态。也可以查看 `D:\1\scripts\master_log.txt`

**Q: 提示"已在运行中"无法启动？**
A: 上一次运行可能未正常结束，删除 `D:\1\scripts\master.lock` 后重试

**Q: 控制台偶尔点了没反应（比如点关闭没反应）、窗口有些位置拖不动？**
A: 有三个原因，已全部修复：
1. 界面主线程每 2~5 秒反复调用 tasklist / adb devices / 查询计划任务，系统命令偶尔
   卡几秒就会让界面“点了没反应”。已改为本地毫秒级进程检测，并把计划任务/ADB 检查
   挪到后台线程。
2. 布局改造时内容层把标题栏盖住了，导致关闭/最小化按钮和大部分标题栏拖拽区域点不到。
   已重新把标题栏置顶。
3. 右上角“操作成功”之类的提示条会临时盖住关闭按钮。已把提示条下移到控制栏下方。
另外，顶部白色控制栏现在按住空白处也能拖动窗口（按钮区域除外）。

**Q: 切号/登录后游戏总弹「维持原有配置」「确认」这类首次启动提示，影响 MAA？**
A: 这是游戏的首次启动/配音包弹窗，根因是槽位里的登录数据缺少游戏写入的「已处理」标记。
脚本已自动处理：登录校验和 MAA 跑完后会把设备上最新的登录数据拉回槽位，已保存的官服槽位
也补上了标记。之后切号不会再弹；若游戏大版本更新后弹窗重现一次，脚本会在本轮自动记住，
下一轮起不再弹出。

**Q: 进基建界面会弹一次指引，导致 MAA「基建换班」卡住/跳过？**
A: 这是「基建站管理」的首次引导弹窗，同样是因为槽位数据缺「已看过」标记
（`key_GB_viewed#BUILDING_STATION_MANAGE`）。官服槽位已补上该标记，且脚本会在每轮运行后
自动同步设备上游戏新写入的标记；若游戏更新后引导弹窗重现一次，下一轮起不会再弹。

**Q: 如何手动切回官服？**
A: 运行 `D:\1\scripts\switch_to_官服.ps1`

## 构建安装包（可选）

仓库附带自解压安装包构建脚本（7-Zip SFX：引导程序 + 压缩的项目文件 +
`setup.bat` → `install.ps1` 安装逻辑）。安装包只包含程序文件，不包含 MuMu/MAA
和 Python 虚拟环境（安装时自动创建并装依赖）。

- 本地构建：
  ```powershell
  powershell -ExecutionPolicy Bypass -File build\build_installer.ps1
  ```
  版本号默认取最近的 git 标签（如 `v1.1.3` → `1.1.3`），也可 `-Version 1.1.3`
  指定。首次运行会自动引导 7-Zip（无需管理员：官方 MSI 用 `msiexec /a` 解压到
  `build\tools`，自解压模块 7zS.sfx 从官方 Extra 包下载）。产物在
  `build\dist\MAA-Farm-Console-v<版本>-Setup.exe`。
- 自动构建（推荐）：推送 `v*.*.*` 标签后，GitHub Actions（`.github/workflows/release.yml`）
  会在 Windows 构建机上自动打包，并把 `Setup.exe` 挂到对应 Release；也可在
  Actions 页手动触发（workflow_dispatch，填要挂载的标签名）。
